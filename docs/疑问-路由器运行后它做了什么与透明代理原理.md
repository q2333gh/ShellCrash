# 我在路由器跑一次 ShellCrash 后，它到底做了什么？

## 先回答你的核心疑问

### 1) 它会不会改 `iptables`？

会。并且不只 `iptables`，还可能改 `ip6tables` 或 `nftables`（取决于配置 `firewall_mod`）。

代码入口：
- `scripts/starts/fw_start.sh`
- `scripts/starts/fw_iptables.sh`
- `scripts/starts/fw_nftables.sh`
- 回滚清理在 `scripts/starts/fw_stop.sh`

### 2) 透明代理怎么实现？

核心是“流量劫持 + 策略路由 + 内核监听端口”三件事：

1. 代理内核启动监听端口
- `mixed-port`（默认 7890）
- `redir-port`（默认 7892）
- `tproxy-port`（默认 7893）
- `dns-port`（默认 1053）
- `controller/db_port`（默认 9999）

2. 防火墙把流量导向这些端口
- Redir 模式：常见是 NAT `REDIRECT` 到 `redir-port`
- Tproxy 模式：`mangle` + `TPROXY`，同时打 `fwmark`
- Tun/Mix 模式：主要走 `MARK` + 策略路由，流量导向 `utun`

3. 策略路由让被标记流量走代理路径
- `ip rule add fwmark ... table ...`
- `ip route add ... table ...`

这样即使客户端没手动配代理，流量也会被网关侧“透明接管”。

## 它在路由器上通常做了哪些事（按启动顺序）

1. 读取配置并准备运行目录
- 读取 `configs/ShellCrash.cfg` 与 `configs/command.env`
- 组装当前内核执行命令（`CrashCore ...`）

2. 处理配置文件
- 下载/校验订阅配置
- 按内核类型改写最终配置（mihomo/sing-box）
- 注入控制端口、UI 路径、DNS 等参数

3. 启动代理内核
- 进程名通常是 `CrashCore`
- 启动成功后进入 `afstart` 阶段

4. 注入网络规则（最关键）
- DNS 劫持（53 -> `dns_redir_port`）
- TCP/UDP 透明转发规则
- 可能建立自定义链（如 `shellcrash*`）
- 可能设置公网入口端口放行/拒绝策略

5. 注入策略路由
- `ip rule` / `ip route`（含 IPv6 场景）
- Tproxy/Tun 时尤为关键

6. 写入自启动与定时任务
- 不同系统接入不同服务体系（procd/systemd/openrc/s6）
- 合并 cron 任务、守护任务

7. 运行时安全与兼容修正
- 例如修复部分环境 DNS 指向
- 在 stop 时尽量清理规则并回滚

## 透明代理在三种主要模式下的差异

### Redir
- 主要拦 TCP（UDP 能力有限）
- 实现简单，兼容性较好
- 典型手段：`nat/REDIRECT`

### Tproxy
- 能更完整处理 TCP+UDP 透明转发
- 依赖内核模块（如 `xt_TPROXY`/mark）
- 典型手段：`mangle/TPROXY + fwmark + policy routing`

### Tun / Mix
- 借助 `utun` 接口接管流量
- 常配合 MARK 与策略路由
- 对复杂场景（如 UDP）更友好

## 你可以在路由器上直接验证这些改动

1. 看进程与监听端口
```sh
ps | grep -i CrashCore
netstat -ntlp | grep -E '7890|7892|7893|9999|1053'
```

2. 看 iptables / ip6tables
```sh
iptables -t nat -S | grep shellcrash
iptables -t mangle -S | grep shellcrash
ip6tables -t nat -S 2>/dev/null | grep shellcrash
```

3. 看 nftables
```sh
nft list table inet shellcrash
```

4. 看策略路由
```sh
ip rule
ip route show table 100
ip -6 rule
ip -6 route show table 101
```

## 总结

你理解得没错：ShellCrash 的“价值核心”不是只起一个代理进程，而是把路由器变成“透明代理网关”。

它确实会动防火墙（`iptables/nftables`）和策略路由（`ip rule/ip route`），再配合内核监听端口，把局域网设备流量按规则接管并分流。
